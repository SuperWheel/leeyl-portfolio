Visible Workflow

DeepSeek Harness 的可视化工作流插件。Agent 先把任务真实做一遍，跑通后再拆成画布上的流程；用户能看清每一步、在节点上批注要改的地方，确认修改后才写入，做过的方法可以保存下来反复使用。

Overview

项目简介

Agent 能连续完成复杂任务，但过程一长，用户就很难看清它做到了哪一步、哪一步依赖哪一步。想把做法保留下来，又要面对手动画流程的成本；用自然语言改长流程时，常常定位不准、改动范围过大。

Visible Workflow 把“做事”和“建流程”的顺序反过来：先让 Agent 真实试做，跑通后由试做记录自动生成流程骨架与草稿；之后每次修改都先变成一份待接受的提案，用户看过影响范围再决定接受或退回。

问题 1

看不清过程

Agent 连续完成复杂任务时，用户难以判断当前步骤与依赖，不知道该从哪里调整。

问题 2

手动画流程成本高

从零拖节点、填配置，搭一条能用的流程要花不少时间。

问题 3

改长流程容易改偏

用自然语言描述修改，定位不准，改动范围容易超出预期。

问题 4

做法留不下来

一次任务的执行方法难以保留，下次同类任务还要重新摸索。

问题来源：PRD v0.4 设计讨论稿。

Prototype

交互原型

还原插件的全屏画布页。点击节点在右侧查看配置；左侧「+」打开节点面板添加节点；选中节点后可「添加注释」；点「查看修改」审阅 Agent 提交的修改提案；点「执行」看节点依次运行。想从头看流程怎么来的，可以点「让 Agent 试做」。

What I did

我做了什么

  • 从问题出发定义需求：梳理 Agent 长任务里“看不清、画不动、改不准、留不下”四个问题，提出产品思路，并把它定位为运行在 DeepSeek Harness 中、基于 Graphon 执行的插件。
  • 与 AI Agent 协作撰写 2 版 PRD：v0.4 设计讨论稿（2026-10-14）提出问题与交互设想；v2.0 需求整合稿（2026-10-16）结合三方竞品横向对比确定方案，按 P0—P2 分期规划交付，设 36 项验收编号（AC-01～AC-36）。
  • 提出“先试后建”：让 Agent 先真实试做、跑通后再拆成流程，由试做记录自动生成流程骨架与草稿，避免先凭空设计一张跑不通的图。
  • 用标准模板降低出错：把节点配置固化为模板，AI 只填业务字段，由后端校验。受控对照中两组各 40 次均成功，模型请求 80→40，修复次数 14→0，Token 约降 52%；对照组是项目内另一方案，耗时未稳定达标，未计入上述结果。
  • 设计变更审核：修改流程先生成待接受的提案，校验版本与固定节点；审核先于写入，退回时目标文件不变。
  • 选定可组合模块方案：由 AI 调研 7 个工作流平台后，我选定可组合模块方案，并沉淀了片段模块。
  • 组织协作开发与验收：拆分任务交给 AI Agent 实现，按验收编号逐项对照，自动测试与真实宿主验收分开记录，未达标项继续跟踪。
